# ADR-0001: 제품 미션 · 1차 출시 스코프

- 상태: Accepted
- 날짜: 2026-05-12
- 결정 확정: 2026-05-14 (DECISIONS.md Q1-Q16 일괄 권장 동의)
- 결정자: lab-trading 메인테이너 (사용자 검토 필요)
- 관련 ADR: ADR-0014 (메뉴), ADR-0015 (출시 페이지), ADR-0019 (백테스트)

## 컨텍스트

사용자가 정의한 출발점:

> "코인, 해외주식, 국내주식 모든것의 정보를 다루는 웹사이트... 메뉴는 대시보드가 있고, 각 카테고리 별로 비슷한걸로 구성하면 될듯. 일단 계획부터 세워볼까? 예를 들면 RSS뉴스, 상승률 랭킹, 하락률 랭킹, 등등의 메뉴를 구상중이야. 백테스트 기능도 생각중이야. 일봉 기준(일봉 이상은 상관없어)."

UI/UX 베이스: yutils (`devtools.krutils.com`) 톤. 배포: Cloudflare.

이걸 그대로 1차 출시에 다 넣으면 6개월짜리 작업이고, 무료 데이터 API 한도와 충돌한다. 어디까지가 1차 출시이고 어디부터가 Phase 2인지 잠가야 ADR-0005~0008(데이터 소스), ADR-0014(메뉴), ADR-0015(페이지)가 다 한 방향으로 정렬된다.

## 검토한 옵션

### A. 3 자산군 시세·랭킹·뉴스 + 백테스트 — 동시 출시
- 장점: 사용자가 처음 그린 비전 그대로. "lab-trading"이라는 이름값 채움.
- 단점: 작업량 큼. 데이터 어댑터 7-8개(코인 3개 + 해외 1-2개 + 국내 2-3개 + RSS 1개) + 캐시 정책 + 차트 + 백테스트 엔진까지 1차에 다 넣어야. **현실적으로 한 사람이 4-6주 작업.** 실패 위험 ↑.

### B. 코인부터 출시 → 해외주식 → 국내주식 → 백테스트 단계적
- 장점: 코인은 데이터 API가 가장 친절(CoinGecko/Binance 무료 + 무인증). 1-2주에 첫 출시 가능. UI·캐시·차트 패턴이 정착한 뒤 같은 패턴으로 해외→국내→백테스트.
- 단점: "통합" 가치가 나중에 와서 초기 사이트는 단순 코인 정보 사이트로 보임. 사용자가 "코인 사이트"로 오인할 수 있음.

### C. 코인 + 해외주식 시세·랭킹 + **백테스트 MVP** 동시 → 국내주식과 뉴스는 Phase 2
- 장점: 백테스트라는 차별화 기능을 첫 인상에 박는다. 코인+해외는 데이터 API 호환성이 비슷해서 어댑터 추상화 검증이 자연스럽게 일어남. 한국 주식 API의 법적 회색지대를 미루는 효과.
- 단점: 국내 주식 사용자 누락. 한국어 시장에서 코스피·코스닥 빠진 정보 사이트는 임팩트 약함.

### D. 3 자산군 시세·랭킹 (백테스트 X) → 백테스트는 Phase 2
- 장점: "통합" 정체성 확보. 백테스트의 데이터 깊이(5-10년 historical) 문제를 미룸.
- 단점: 차별화가 약해진다. 시세·랭킹만으로는 toss/Investing.com 클론.

### E. 코인 시세·랭킹 + **백테스트** + (해외/국내는 stub 페이지) 동시 출시
- 장점: 1차 출시는 작지만 "3 자산군 + 백테스트" 메뉴 구조는 처음부터 박힘. stub 페이지는 "준비 중 — 다음 분기" 안내. 백테스트 우선 도그푸딩.
- 단점: stub 페이지가 SEO에 악영향. 비어있는 메뉴는 사용자 신뢰 떨어뜨림.

## 결정

**옵션 C 채택 권장.**

근거:
1. **코인+해외 동시 출시는 데이터 API 호환성이 높다.** CoinGecko·Binance·Twelve Data 모두 REST + JSON + fetch() 기반이라 동일한 어댑터 인터페이스(`DataAdapter`)에 깔끔하게 맞는다. 자산군별 어댑터 추상화는 첫 두 자산군에서 검증되어야 세 번째(국내) 점등 시 비용이 가장 낮다.
2. **국내 주식은 데이터 소스 결정에 시간이 필요하다.** KIS Open API는 계좌+키 필요, 네이버 unofficial은 ToS 회색지대, KRX는 신청·승인 절차가 있다. ADR-0007에서 단독으로 다루며 Phase 1.5 정도로 늦추는 게 현실적.
3. **백테스트는 1차 출시에 필수.** "lab-trading"이라는 도메인 이름과 사용자 요구사항이 명시적으로 백테스트를 포함한다. 백테스트 없는 1차는 "또 하나의 가격 사이트"가 된다.
4. **뉴스/RSS는 Phase 2.** 무료 RSS 큐레이션은 데이터 신뢰성과 ToS 검증이 필요하고, 1차 출시 가치 명제에서 우선순위가 낮다. ADR-0008에서 별도 검토.

**1차 출시 스코프 (Phase 1):**
- 자산군: 코인(crypto) + 해외주식(us)
- 페이지: 대시보드 + 자산군별 시세 인덱스 + gainers/losers/volume 랭킹 + 종목 상세
- 차트: 캔들 + 거래량 (lightweight-charts) + 카드 스파크라인 (자체 SVG)
- 백테스트: 일봉 기준 buy-and-hold / SMA crossover / RSI 3개 preset
- 데이터 소스: CoinGecko Demo + Binance public + Upbit public + Twelve Data
- i18n: ko 단독 (en은 메시지 파일만 잠금)
- 사용자 데이터: localStorage (즐겨찾기·테마·전략 프리셋)

**Phase 1.5 (1차 출시 후 2-4주):**
- 국내주식(kr) 자산군 추가 (KIS Open API 또는 KRX 정식 채택 — ADR-0007 결정 따라)

**Phase 2 (1차 출시 후 1-2개월):**
- 뉴스/RSS 페이지
- 영어 i18n 활성화
- 백테스트 전략 확장 (MACD, 볼린저 밴드, 사용자 정의 표현식)

**Phase 3+ (필요 시):**
- 사용자 계정 + 클라우드 동기화 (ADR-0016 결정 따라)
- 결과 공유 페이지 (`/backtest/share/[id]`)
- 분/시간봉 시세 (백테스트는 영구 일봉 한정)
- 옵션/선물/ETF 확장

## 결과

### 긍정적
- 1차 출시 작업량이 4-6주 → **2-3주**로 압축.
- "통합 사이트 + 백테스트"라는 차별 가치를 첫 인상에 박는다.
- 어댑터 추상화가 자연스럽게 검증된다 (코인 + 해외 두 자산군).
- 데이터 소스가 무료·무인증 위주라 첫 배포 시점 운영 비용 0.

### 부정적
- **국내 주식 사용자 누락** (Phase 1.5까지 1-2개월). → 완화: 메인 페이지·footer·메뉴에 "코스피·코스닥은 곧 출시 예정" 안내. SEO sitemap에는 제외.
- 뉴스 누락 — 한국 사용자에게 "정보 사이트"의 인상이 약해질 수 있다. → 완화: 대시보드에 "관련 외부 링크" 위젯으로 임시 대응.

### 따라오는 작업
- ADR-0005 (코인 데이터): CoinGecko Demo + Binance + Upbit 채택 확인
- ADR-0006 (해외 데이터): Twelve Data 채택 확인 또는 대안
- ADR-0007 (국내 데이터): Phase 1.5 도입 시점에 결정 가능하도록 옵션 비교 잠금
- ADR-0014 (메뉴): 1차 출시 시 국내·뉴스 메뉴는 disabled 또는 "준비 중" 라벨
- ADR-0015 (출시 페이지): Phase 1 페이지 셋 확정
- ADR-0019 (백테스트 엔진): 클라이언트 사이드 권장
